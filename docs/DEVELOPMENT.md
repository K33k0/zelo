# Developing Zelo

## First checkout on Windows

Install Git, Node.js with npm, PowerShell, and JDK 17. Set `JAVA_HOME` to the JDK directory. Android builds also need Android SDK platform 35 and the build tools selected by Gradle; install them through Android Studio SDK Manager and set `ANDROID_HOME` to that SDK directory. Keep signing keys and personal progress out of Git.

```powershell
./scripts/setup.ps1
npm test
$env:PLAYWRIGHT_BROWSERS_PATH = "$PWD/.tools/browsers"
npm run test:browser
./scripts/test-native.ps1
./scripts/build.ps1
```

Setup installs locked npm dependencies, Chromium into `.tools/browsers`, and org.json 20240303 from Maven Central, verifying its SHA-256. Use `-SkipBrowser` to omit Chromium. Setup needs internet access; it does not install Java or the Android SDK. Native tests prefer the existing bundled JDK, then `JAVA_HOME`, then Java on PATH. Override the JSON jar with `ZELO_JSON_JAR` if needed.

The Gradle wrapper downloads Gradle on first use. The build script uses bundled tools when available, otherwise the wrapper and configured SDK/JDK. `dist/zelo-debug.apk` is generated by the build; it is intentionally ignored by Git. Use the same debug signing key for in-place updates: a new machine's key may differ. Back up progress before changing signing keys or reinstalling.

## Checks and formatting

- `npm test`: pure planning, validation, copy and backup parsing.
- `npm run test:browser`: browser flows with a fixed clock; starts the local preview on port 4173. Close an unrelated server on that port before testing.
- `./scripts/test-native.ps1`: Java/JavaScript parity plus reminder and backup-archive regressions.
- `./scripts/build.ps1`: Android debug assembly and lint, then copies the APK into `dist`.
- `npm run format` and `npm run format:check`: pinned Prettier with the Java plugin. Formatting covers source, tests and docs.

For device-only tests, configure JDK/SDK as above and use `./gradlew.bat connectedDebugAndroidTest` with a connected test phone or emulator. The storage tests isolate preferences with a `qa-` prefix; they do not use real challenges. Device tests verify actual Android persistence and recovery, which the browser bridge mocks cannot prove.

For preview use `npm start`, then open http://127.0.0.1:4173. Browser progress is separate from phone progress. Generated screenshots, build products, SDKs and dependency caches are ignored.

## Source map

| Path                                                      | Responsibility                                                   |
| --------------------------------------------------------- | ---------------------------------------------------------------- |
| `app/src/main/assets/www/core.js`                         | Pure planning, dates, validation and backup parsing              |
| `app/src/main/assets/www/app.js`                          | Rendering, forms, browser persistence and Android bridge calls   |
| `app/src/main/java/com/stride/challenges/GoalEngine.java` | Native widget/reminder calculations; kept in parity with core.js |
| `ProgressStore.java`                                      | Native source of truth, revisions, widget logging and recovery   |
| `MainActivity.java`                                       | Restricted WebView, bridge, file picker and lifecycle            |
| `ReminderPolicy.java`, `ReminderReceiver.java`            | Reminder timing and delivery                                     |
| `BackupArchive.java`, `BackupService.java`                | Versioned archives and document-provider writes                  |

Normal Android saves compare revisions to reject stale forms. Recovery compares the complete original raw snapshot, because malformed data may not have a readable revision. A successful recovery atomically preserves the original alongside the replacement. Widgets, reminders and backups refresh after native changes. Browser storage is local to one browser and is not a multi-device synchronization mechanism.

## Git

The repository uses `main`. Commit source, tests and documentation together when they describe one fix; keep formatting separate from behavior changes. Run the relevant checks before committing. No remote is configured automatically: choose a private host and push only when ready. Existing local Git author settings are used.
